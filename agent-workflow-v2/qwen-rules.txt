LOCAL QWEN CODING WORKFLOW
Before changing a stateful function, search selected files for its callers and
the state fields it changes. Inspect the producer and consumer together;
event handlers and frame loops can call the same helper at different times.
Consume mouse displacement once as a transient angular change. Keyboard turn
input is a continuous rate. Clearing a shared input object before simulation
uses it can discard the event instead of stopping repeated motion.

These rules apply only to this explicitly launched Pi workflow, including its
explicit ChatGPT comparison executor. They do not change Codex settings.
Accept existing project architecture.md as written, regardless of line count or
file size; do not shorten it merely to satisfy a size target. Include it in scope
when architectural decisions change. Its generated
shadow counterpart maps current prototypes and refreshes automatically.
On explicit resume, preserve current partial edits and accepted todos. Use the
supplied progress brief and fresh context; never replay the entire conversation.
Follow the project's existing instructions and current user authorization.

Work on one independently testable behavior per task in a disposable worktree.
The launcher has already frozen the goal, acceptance cases, allowed files and
CPU test commands in the supplied task state. Use that contract; do not create
another plan or run begin yourself during coding.
Default file target is 150-250 lines; gate new source at 300 lines and 32 KiB.
Target functions of 10-40 lines; gate new functions at 60 lines. Existing oversized
code may be fixed without growth; extract coherent responsibilities when needed.
Nested functions count toward their enclosing function's line span. Extract
cohesive operations to module scope with explicit state/dependencies when needed.
Do not split code merely to satisfy line counts or create generic helper dumping grounds.

Separate deterministic logic from filesystem/network/process/model adapters.
Pass clocks, paths and external clients as dependencies. Keep imports free of work.
Every new function needs a brief docstring or adjacent description and testable inputs.
Test changed behavior, failure handling and boundary cases with small CPU fixtures.
Mock external boundaries; tests must never load a model or start production generation.
A test passing is evidence for that test's behavior, not proof every function is tested.

Start navigation with project_map catalog and locate, then inspect relevant prototypes.
When a todo supplies exact paths, begin with inspect directly instead of redoing
the whole catalogue. Inspect can select up to 8 space-separated symbol names;
source_query symbol can retrieve the same small named batch in one file.
The launcher may supply a BOUNDED LOCAL EXECUTOR PACKET. Its current interfaces,
small editable files, named dependency spans, primitive module literals and pinned test pages have already
been retrieved. Use them directly. Retrieve only omitted or changed spans.
Do not repeat an identical retrieval against unchanged source. Once the needed
contracts and implementations are read, implement the task and run its tests.
Repeated identical navigation aborts the attempt for review.
Read actual implementation before editing; the shadow has interfaces, not full behavior.
Use project_map to find paths; source_query search uses rg -n -F in 1-5 selected files.
Use source_query symbol to read a named function in pages of at most 120 lines.
Use source_query variables to inspect names, scopes and declared types without values.
The coding tool set is project_map, source_query, edit, write, workflow_test and
web_research. Use research only to resolve a concrete uncertainty; distill source
evidence into a short cited brief. Raw pages stay outside the project and context.
arbitrary shell and unrestricted reads are intentionally absent from this workflow.
The exact external acceptance fixtures in declared test argv lists are pinned by
hash and can be retrieved read-only. Their contents cannot be edited by this agent.
Use source_query action fixture to read a pinned test page once; query may be empty.
Aim for 3-6 batched navigation calls before editing. More than 12 navigation calls
against unchanged source is blocked: implement from evidence or split the task.
Do not paste a whole repository, unrestricted recursive grep, or huge test logs into context.
Limit each tool result to roughly 8 KiB; keep the complete artifact outside model context.
Pi refreshes the shadow after EVERY edit/write and again at completion.
A refresh failure blocks completion. Check source hashes before relying on a saved prototype.
Missing descriptions are debt requiring review, never invented guarantees.

Keep a task to at most 8 files including required docs and tests, and 300 changed lines.
When a task is larger, split it into independently verified behavior changes.
Finish a change by workflow.py test then workflow.py check. Any edit invalidates prior tests.
In Pi use workflow_test, then project_map gate with the frozen state-file path.
Completion requires current generated prototypes plus fresh passing test evidence.
For application integration, check the composition root: importing a module does
not invoke its exported initializer. Match public call signatures and supply
required adapter/data arguments; initialize shared dependencies once.
Optional browser/platform APIs can reject even when their methods exist. Handle
rejected promises and provide usable controls when a required input feature is
unavailable. Use the supplied environment evidence instead of investigating
unrelated styling. Verify actual startup and handlers, beyond symbol presence.
For interactive input, mouse movement is a transient delta: stopping movement
must stop mouse-driven turning. Keep held-key input separate from mouse deltas;
verify aiming remains stable after the cursor leaves the canvas. Initialize the
browser composition root exactly once; inspect any existing entry call first.
An exposed state property must stay a live object when internal state is replaced;
do not substitute a callable state() for a documented .state object. Restart must
restore a playable session with working movement and firing handlers. Teardown
and reset are different lifecycle operations; verify real input after restart.
Review acceptance cases and public interfaces, then save one patch or commit per task.
At a composition root, call the accepted factory instead of replacing its result
with an inline reduced example. Module tests alone do not establish that the live
application uses that module. Verify runtime dimensions/content and restart state.
For UI visibility, verify computed display and real pointer interaction. Setting
hidden alone can leave an overlay visible when author CSS sets display:flex.
Repair the selected UI adapter and verify actual clicks after state transitions.
Do not auto-commit, stage unrelated work, or refactor unrelated modules.

Use the selected todo's explicit input, output and thinking budgets. Private
profiles default to 24k input / 16k output and a requested medium thinking budget of 4k.

with a requested 8k thinking budget. The main MTPLX server's verified native guard
defaults to 4096; private Pi overrides it with the effective per-request task cap. Mechanical edits may
disable thinking. Input/output limits are caps,
not token targets. Output includes thinking, code and tool-call content.
Small and standard presets fit a64k window; large needs at least 96k. The small preset fits a32k
window with8192 tokens of template headroom. Count the whole request as input,
including instructions, schemas, selected source, history and failure evidence.
Do not spend the thinking budget on repeating the prompt or reading known spans.
Budget exhaustion can truncate a response before an edit; it is not completion.
If the focused contract does not fit, stop with the specific missing prerequisite.
27B is capped at 96k. Flash Next is capped at 128k. Even at those ceilings,
start with a compact task preset rather than filling the larger window.
The client window must not exceed the verified server window. A smaller client
window is a history budget, not a reduction of server-allocated KV memory.
do not raise context just because this document describes a larger budget.
Compact between atomic tasks with goal, scope, changed symbols, test evidence,
remaining failures and next action. Preserve stable prefix text for caching.
